## 3. Conflicts / risks for a new mobile layer

1. **Inline `!important` beats stylesheet `!important`.** `applyPanelBox()` (`index.js:4952` region) writes
   `left/top/width/height` with priority `important`. If any path calls it while `isMobileLayout()` is false on a real phone
   (rotating a tablet, a resize handler, a future caller), the full-screen mobile rules *silently lose* and the panel becomes a
   fixed 1100x800 box. **Mitigation:** make `applyPanelBox` early-return on `isMobileLayout()`, or switch it to CSS custom
   properties (`--cv-panel-w` etc.) so stylesheets keep authority.
2. **`#chatvault_overlay` / `#chatvault_panel` base rules are already `!important`** (`style.css:141-163`). Any mobile rule for
   those two selectors that omits `!important` loses regardless of order. Every other selector can drop it.
3. **`@media (min-width: 721px)` desktop blocks also match landscape phones** (844 > 721): they install `.cv-resize-handle`
   (display:block), `.cv-drag-strip`, `.cv-mode-dock`, `.cv-window-positioned` and `cursor:move` on `.cv-header`. The landscape
   layer must keep neutralising them explicitly (it does at `3632`-`3666`); if that block ever moves above `2222`, landscape
   phones get drag handles again.
4. **Three competing sources for the same selectors**: legacy `<=720` blocks, the `min-width:721 + .cv-layout-narrow` block
   (`2103`), and the new layer. `.cv-organizer-row` is defined four times (`1031` base, `1402`, `2155`, `3499`). A 5th
   definition anywhere but last is a guaranteed regression - see section 2 item 1.
5. **`position: fixed` descendants of a transformed ancestor.** `.cv-window-positioned #chatvault_panel` sets
   `transform:none!important` today, which is exactly what keeps `.cv-msg-menu` / `.cv-preview-tip` escaping `overflow:hidden`.
   If anyone reintroduces a non-`none` transform (scale/translate animation, `will-change:transform`, `contain:paint`) on the
   panel, both popovers become clipped inside the panel and the mobile bottom sheets break. Prefer `position:absolute` (M-05) so
   this dependency disappears.
6. **`100vw` / `100vh` in the base layer** (`144`, `145`, `161`, `162`): `100vw` includes the scrollbar (horizontal overflow on
   desktop); `100vh` is the *large* viewport on iOS, so any non-phone media query that still uses `92vh` (`162`) is taller than
   the visible area. The mobile block re-declares with `%` / `var(--cv-vv-h)`, but the base values remain the fallback for
   tablets.
7. **Duplicate safe-area semantics**: `max(12px, env(...))` (`346`) pins content *onto* the inset, `calc(10px + env(...))`
   (`3117` region) lifts it *above*. Both now target the pagination pill. Pick `calc` + inset and audit every `env()` for the
   same ambiguity - a mixed convention is how a pill ends up half under the home indicator on one device and detached on another.
8. **`body.cv-scroll-locked` is the only lock, and it locks the wrong scroller** (M-01). If you keep it, also consider
   `documentElement` + `overscroll-behavior:none`, and gate it on `isMobileLayout()` so the desktop dock/free modes keep
   working - otherwise the "operate the tavern at the same time" feature ships broken.
9. **Inline `onclick="event.stopPropagation()"`** (`index.js:912`, and every modal) is load-bearing for tap-through protection
   (M-53). A CSP tightening turns "tap inside the panel" into "close the panel". Convert to listeners first.
